# Панель використання для DeepSeek Harness

[English](README.md) | [Русский](README.ru.md) | **Українська**

**DSH 0.2.2-rc.1**, плагін **0.1.1**. Окреме розширення під контролем користувача; воно не змінює архів застосунку, плагін OAuth, конфігурацію моделей, сховище облікових даних чи білінг.

## Інтерфейс

- **Usage** на панелі елементів керування редактора повідомлень відкриває стислий звіт за сеансом і останнім викликом. Наявні вбудовані віджети токенів за всім журналом і контексту залишаються без змін. Доданий індикатор показує лише вартість, щоб не дублювати вбудований індикатор токенів.
- **Usage** на бічній панелі відкриває окрему сторінку з вкладками Sessions / Models / Days, фільтрами дат за місцевим календарем, графіком щоденного використання токенів з обмеженою кількістю даних і поступовим завантаженням історії. **Close** у правому верхньому куті повертає до Conversation через вбудований сервіс компонування, не закриваючи й не перемикаючи поточний Session.
- Звіти показують **власні виклики із зафіксованим підсумковим обліком використання**. Скопійована історія розгалуження або початкового наповнення не враховується: її початкове використання належить сеансу-предку. Заповненість контексту показується окремо й не є сукупним споживанням токенів.
- Історія завантажується по п’ять сеансів. Підсумки та графіки описують **завантажені сеанси**, а не весь обліковий запис. Refresh починає формування знімка заново; якщо термін дії курсорів минув, потрібен Refresh. Саме вбудоване отримання переліку заголовків не має посторінкового поділу.
- Групування за днями використовує показаний часовий пояс IANA та збережені часові позначки підсумкового обліку, а не дату створення сеансу чи рахунка від постачальника. Відсутні дати чи дані використання, недоступні сеанси та обрізання даних позначаються явно.

## Що означають показники

Input — це вхідні токени без кешування. Читання з кешу та запис у кеш — окремі категорії, що не перетинаються; токени міркування вже входять до вихідних токенів. Відсутні значення залишаються недоступними, а не прирівнюються до нуля. Достовірний підсумковий показник постачальника може підтвердити, що значення відсутньої категорії кешу дорівнює нулю; інакше воно залишається невідомим.

Остаточний зразок даних використання замінює попередні зразки для тієї самої спроби. Повторний запит додає ще одну спробу. Пізніший неповний підсумковий запис не стирає вже отриманий зразок: відомий проміжний підсумок зберігається з позначкою неповноти. Редагування вмісту в інтерфейсі чи ущільнення контексту не скасовують попереднього споживання. Обліку підлягають лише записані підсумкові дані повідомлень асистента та спроб; розширення не вигадує незаписані допоміжні запити чи нарахування на боці постачальника.

Суми в доларах — це **оцінки за каталогом, еквівалентні вартості API, а не списані кошти, рахунок, кредитний баланс, права за підпискою чи залишок квоти**. Для них використовується публічний каталог pi-ai **1.3.0**, що постачається з цією версією DSH, точні ключі постачальника й моделі та пороги тарифних рівнів для кожного виклику. Вони не враховують історичних змін тарифів, перевизначень для кінцевих точок, знижок чи фактичних комерційних умов профілю.

Відомі маршрути, які можуть працювати за підпискою або токенним планом, із міркувань обережності виключаються з доларових оцінок. **Subscription / not calculated** — це правило відображення, а не доказ того, що історичний запит використовував OAuth: загальні збережені заголовки не містять типу його автентифікації. Зокрема, токени ChatGPT/Codex не перетворюються на вигадану плату за підписку. Для невідомих псевдонімів чи моделей, синтетичних цін, усі значення яких нульові, відсутніх лічильників і неоднозначного терміну зберігання даних під час запису в кеш вартість не визначається. Підсумки, у яких оцінено вартість лише частини даних, позначаються як неповні.

Зафіксоване визначення одиниці вартості наведено в [документації моделей pi 1.3.0](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/rpc-commands.md): долари США за мільйон токенів.

## Конфіденційність і контроль допуску

Host реєструє лише два POST-обробники з точним збігом шляхів у **наявному транспорті Connection DSH з автентифікацією власника**. Нові сервери чи слухачі, дозволи чи надання доступу, шаблони Gateway з підстановкою або засоби отримання облікових даних не створюються. Вбудована перевірка допуску транспортного рівня відбувається перед цими обробниками; додатково вони вимагають JSON, заголовок `X-DSH-Usage: 1`, що робить запит непростим у термінах CORS, вхідні дані обсягом не більше 4 КіБ і перевірки Origin/Host. У штатному мосту Desktop заголовок Origin може законно бути відсутнім. Необроблені вхідні значення сеансу, схожі на шляхи, відхиляються.

Спостереження за історією виконується локально, лише для читання, через `sessionQuery.observeSession` з `projectionMode: 'none'`; вбудована реалізація всередині читає та перевіряє збережені журнали. Жоден неактивний Agent не приєднується й не відновлює роботу. Розширення вибирає лише лічильники використання, записані ідентифікатори маршрутів і часові позначки подій та звільняє кожну оренду спостереження. Воно ніколи не повертає текст повідомлень, потоки, заголовки, інструменти, cwd, назви, посилання на облікові дані, шляхи чи необроблені винятки. Сховище облікових даних, ключі середовища та API виявлення моделей не перевіряються.

Очищені агреговані дані та знімки з непрозорими курсорами мають обмежений розмір, зберігаються в пам’яті та ізольовані за профілем і ідентичністю сервісу. Проксі Cordis порівнюються за канонічною ідентичністю, а виклики й надалі проходять через проксі з трасуванням. Це розширення не перезаписує журнали сеансів і кеші проєкцій. Наше обмеження групи до п’яти сеансів не перетворює вбудоване завантаження журналів неактивних сеансів на посторінкове читання байтів. Обмеження кількості подій, викликів і потоків у сеансі призводять до звітів із явною позначкою неповноти.

## Перевірка та збирання

Використовуйте Node.js 22 або новішу версію. Залежностей для виконання чи розробки, які потрібно встановлювати, немає.

```sh
npm run build
npm run check
npm test
npm run test:native
```

Детерміновані тести охоплюють облік, повторні спроби й розгалуження, невідомі значення, ціни й межі тарифних рівнів, ідентичність профілів і проксі, скасування та звільнення ресурсів, посторінкову навігацію за курсорами, часові пояси, життєві цикли контролерів інтерфейсу та формат запитів транспорту з перевіркою власника. Тестові фікстури компонентів і контролерів — **не перевірка в реальному браузері**.

Необов’язкова команда `test:native` потребує macOS і відповідної встановленої версії застосунку Desktop. CI виконує лише переносимі перевірки збирання, синтаксису та детермінованих тестів.

Нативний smoke-тест використовує фактично встановлені Cordis, SessionStore, SessionQuery, fiber плагіна та механізм перевірки власника Connection, з новим ізольованим Context у пам’яті й синтетичною браузерною автентифікацією. Він не відкриває сокетів, не читає профіль, журнали чи облікові дані користувача та не надсилає запитів до моделей чи мережі. Синтетичні фікстури підтверджують контракт інтеграції, а не відображення в реальному браузері чи фактичні нарахування за обліковим записом.

Попередньо зібраний браузерний артефакт генерується з власного вихідного коду та самодостатніх арифметичних обчислень. Він завантажує лише React, наданий хостом, без імпортів приватних клієнтських значень і без другого рендерера. Йому не потрібен процес стеження за змінами для розробки чи альтернативний сервер GUI. Для іншої версії DSH потрібна повторна перевірка контракту, а не виняток із вимог сумісності.

Щоб повторно згенерувати знімок фактичних цін, запустіть генератор через вбудований Electron у режимі Node або передайте йому аргументом кореневий каталог витягнутого **публічного коду SDK**. Він розбирає лише JSON каталогу постачальників, ніколи не імпортує засоби виявлення моделей чи автентифікації й ніколи не читає налаштування.

## Встановлення / відкат

Клонуйте репозиторій у постійний каталог: встановлений плагін посилається на цю робочу копію. Для використання попередньо зібраного браузерного артефакту, включеного до репозиторію, не потрібні ні npm install, ні збирання. Використовуйте вбудований CLI, що відповідає запущеному застосунку, а не старішу глобально встановлену команду `dsh`:

```sh
git clone https://github.com/rooty/dsh-usage-dashboard.git
cd dsh-usage-dashboard
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add "$PWD"
```

Повністю закрийте DSH за допомогою **⌘Q**, відкрийте його знову, а потім перевірте індикатор Usage у редакторі повідомлень і сторінку Usage на бічній панелі в наявному GUI. Виходити з облікового запису, повторно авторизуватися, надавати ключ API чи змінювати постачальника не потрібно. До цієї ручної перевірки інтерфейс є попередньою версією з перевіреним збиранням, а не підтвердженням успішної роботи в реальному GUI.

Щоб скасувати вибір пакета, не видаляючи розмов чи облікових даних:

```sh
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop remove @local/dsh-usage-dashboard
```

## Відомі обмеження

- Сумісність зафіксовано для DSH **0.2.2-rc.1**; інші версії потребують повторної перевірки.
- Індикатор вартості в редакторі повідомлень наразі не підписується на оновлення підсумкового обліку, коли спливне віконце закрито. Відкрийте Usage або натисніть Refresh, щоб завантажити актуальні значення; доки спливне віконце відкрите, воно оновлюється кожні десять секунд.
- Збирання, фікстури та нативні smoke-тести не підтверджують відображення в реальному браузері чи фактичні нарахування за обліковим записом.
